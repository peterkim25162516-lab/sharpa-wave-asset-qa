# Sharpa WaveSimParity｜讲人话版：我们做了什么、发现了什么

> 这是一份给非仿真专业读者看的说明书。它不要求你先懂 URDF、MuJoCo、PhysX 或机器人动力学。
>
> 想核对全部技术细节、实验身份、证据链和复现步骤，请看[技术完整版飞书文档](https://sjtu.feishu.cn/wiki/ASRQwjR7EiSvRJk7eqrctveOnug)。

## 0. 三十秒结论

这个项目做了两件事：

1. 先给 Sharpa Wave 机械手的模型文件做一次系统“体检”，确认不同格式里的关节、几何和运动学是否彼此对得上；
2. 再让 MuJoCo 和不带渲染器的 OVPhysX 用同一只手、同一组动作、同一套评分规则做“同题考试”，看两个模拟器会不会给出足够接近的结果。

目前最诚实的结论是：

- 模型资产整体质量很好。v0.1 共得到 `497 PASS / 6 KNOWN / 13 WARN / 0 FAIL / 0 SKIP`；
- 标准左右手的 44 个关节全部完成映射，10 个指尖相关坐标系全部完成核对；
- 所有正式实验都跑完了，没有出现 NaN、数值爆炸或莫名中断；
- 两个模拟器的关节角和末端姿态通常很接近，但末端位置差在多个无接触动作里略微超过事先定好的 `2.000 mm` 线；
- 接触实验 C0 的唯一失败项，是 OVPhysX 对“松开接触的时刻”在两种时间步长下相差 `5.5 ms`，高于预先规定的 `4.0 ms`；
- 因此，当前不能把项目写成“两个模拟器已经完全一致”，也不能说“某个官方软件有 bug”。准确说法是：实验有效、证据可复核，但部分指标超过了预设容差，或还不足以支持明确归因。

这是一个**非官方、纯仿真**项目。硬件实验、Sim2Real、真实安全性和官方产品认证都不在范围内。

## 1. 这个项目到底在解决什么问题

机器人公司通常会同时提供多种模型文件。可以把它们想成“同一个机器人，被写成了几种不同说明书”：

- URDF 常用于 ROS 生态，擅长描述机器人由哪些连杆和关节组成；
- MJCF 是 MuJoCo 常用格式，除了结构，也包含更多仿真设置；
- USD/USDA 是 OpenUSD 生态的场景描述格式，PhysX 相关属性也可以挂在上面。

问题在于：文件都能打开，不代表它们描述的是完全同一台机器人。名字可能对不上，关节方向可能相反，零位可能不同，指尖坐标系也可能有微小偏差。即使静态结构完全一致，两套物理引擎对摩擦、驱动器、求解器和时间积分的解释仍可能不同。

所以项目不是在问“模型能不能加载”，而是在依次问：

1. 这些文件内部有没有明显问题？
2. 不同格式是否描述了同一套关节和几何关系？
3. 两个模拟器执行同一动作时，结果差多少？
4. 差异是偶然噪声、时间步长问题，还是某类参数的系统影响？
5. 加入接触后，实验本身是否仍稳定到足以比较？

## 2. 我们怎么保证这是“同题考试”

跨模拟器比较最怕“表面上动作一样，实际上输入不一样”。为此，项目先把题目、名字和评分方式全部冻结。

### 2.1 一张封好的考卷

每次正式实验都有一份固定的场景清单。它规定：用左手还是右手、动哪个关节、跑多久、时间步长是多少、什么时候发命令、记录哪些量、用什么阈值判定。

这就像考试前把试卷封好。跑完以后不能因为结果不好看，临时改题或改及格线。

### 2.2 一张统一点名册

同一个关节在两种文件里可能名字不同。项目没有靠“看起来差不多”来猜，而是建立了明确映射，并检查关节顺序、方向、零位和上下限。

最终标准左右手共 `44/44` 个关节完成映射，左右手共 `10/10` 个指尖相关坐标系完成核对。

### 2.3 每次都开一个全新的考场

正式 case 使用新的操作系统进程启动，避免上一次运行留下的缓存、随机状态或全局设置污染下一次结果。

“重复运行”也不是在同一个程序里按两次播放，而是重新启动后再完整跑一遍。

### 2.4 把时间刻度切得更细再做一次

实验既用基础时间步长，也用减半后的时间步长。可以把它理解成：同一段运动既用普通帧率拍，也用更高帧率拍。如果结论随时间刻度明显变化，说明结果可能还受数值离散影响，不能急着做跨模拟器结论。

### 2.5 给每份证据贴“防拆封条”

源码、输入、原始输出和最终报告都有内容哈希与清单。哈希类似文件指纹：内容改一个字符，指纹就会变。

它不能证明物理结论天然正确，但能证明“现在看到的内容是不是当时那一份”，也能防止不小心混用旧实验与新实验。

## 3. 第一阶段：先给模型文件做体检

v0.1 是 CPU 优先的资产 QA，不需要先跑大规模 GPU 仿真。

项目共检查 60 个模型入口：

- 15 个 URDF；
- 15 个 MJCF；
- 30 个 USDA。

检查内容包括：文件能否解析、引用的网格是否存在、关节和连杆是否自洽、左右手与不同格式的关节集合是否匹配，以及同样的关节角度下，指尖应该出现在什么位置。

最关键的运动学检查可以理解为：不用考虑重量、惯性和摩擦，只按关节几何一路算到指尖。项目用固定随机种子生成了 `256` 组合法关节姿势；标准左右手的 URDF 与 MJCF 结果几乎重合：

- 最大位置差约 `0.00007073 mm`；
- 最大姿态差约 `0.00008585°`。

这比后续毫米级差异小了很多个数量级，说明“基础骨架被翻译错了”不是主要嫌疑。

v0.1 共完成 `516` 项检查，最终结果为：

| 标签 | 数量 | 人话解释 |
|---|---:|---|
| PASS | 497 | 检查通过 |
| KNOWN | 6 | 已知且有来源记录的问题，不冒充本项目首次发现 |
| WARN | 13 | 值得说明，但不足以判失败 |
| FAIL | 0 | 没有新的硬失败 |
| SKIP | 0 | 没有跳过检查 |

其中 3 个双手 MJCF 的网格目录加载问题已经由上游 PR 处理，因此被如实记为已知项；腕部/法兰附近约 `29.0–29.5 mm` 的稳定偏移被记为警告，因为它更像明确的坐标定义差异，而不是随机损坏。

这里必须加一句边界：v0.1 对 USDA 做的是文本和结构层检查，不等于已经用 PhysX 把所有 USD 动力学都跑过一遍。

## 4. 第二阶段：让两个模拟器做最小无接触考试

正式 Gate 0 比较的是：

- 本地 MuJoCo；
- 远端、纯 headless、无 Kit/渲染器/相机的 kit-less OVPhysX。

因此它不是“完整 Isaac Sim 渲染流程对比”。两边都使用固定基座、单只左手或右手、22 自由度、位置控制，不加入接触，也不做双手和浮动基座。

考试题包括：

- 保持零位；
- 在重力下稳定；
- 给关节一个很小的阶跃命令；
- 同样实验用基础与减半时间步长运行；
- 每组再从新进程完整重复。

结果：

- `32/32` 场景完成；
- 44 个关节与 10 个指尖相关坐标系覆盖完整；
- 没有 NaN 或数值爆炸；
- 新进程重复结果完全一致；
- 时间步长减半检查通过；
- 零位保持与重力稳定通过；
- 关节差和姿态差通过阈值；
- 左右手小阶跃的末端位置最大差分别为 `2.109 mm` 和 `2.111 mm`，略高于预先设定的 `2.000 mm`。

所以正式标签是 `DIVERGENT`，并且 `pass_ready=false`。

`DIVERGENT` 的意思只是“至少一个指标超过双方事先同意的容差”，不等于“OVPhysX 错了”“MuJoCo 错了”或“官方资产有 bug”。

## 5. 发现差异后，我们怎样顺藤摸瓜

Gate 0 告诉我们“哪里超过线”，但没有直接告诉我们“为什么”。后续做了三类诊断。

### 5.1 把 MuJoCo 的关节干摩擦拿掉

在选定轨迹上，去掉 MuJoCo 的关节干摩擦后，跨模拟器差异明显下降：

- 关节最大差下降约 `51.36%`；
- 指尖位置最大差下降约 `59.67%`；
- 姿态最大差下降约 `75.86%`；
- 整体均方根误差下降约 `89.48%`。

这说明关节干摩擦是一个重要贡献因素。但这只是受控干预，不足以说它是唯一原因，更不能据此说某一边实现错误。

### 5.2 调整总粘性阻尼

统一调整控制器的粘性项后，不同关节反应不一致：小指的选定窗口改善约 `82.36%`，拇指只改善约 `4.22%`。

这更像“局部有效、不能一刀切”。结论是混合的，而不是找到了一组万能参数。

### 5.3 把两边轨迹放进同一套几何计算

项目把两个模拟器产生的关节轨迹，都送进同一个前向运动学模型重新算指尖位置。公共几何模型自身的残差只占约 `0.0053%`，两组候选轨迹都得到 `CLOSES`。

人话解释是：指尖位置差基本跟着关节状态差走，不是因为两边用了不同的“尺子”算指尖。但这一步仍没有解释关节状态为什么不同。

## 6. 为什么不能把两边参数直接抄成一样

R1 做的是只读参数回读：不跑轨迹，只问两个引擎“你最终实际用了什么参数”。

44 个关节全部读取成功，并在 4 个全新进程中精确重复。读取覆盖摩擦、附加转动惯量、控制/驱动和求解器/运行时设置。

最终四类都保守标为 `UNMAPPABLE`。这不是“没有读到数字”，而是“两家产品对同名概念的定义和作用层次不完全一样，现有证据不足以承诺一一等价”。

可以类比两辆车的“油门 30%”：数字一样，不代表发动机扭矩、变速箱响应和车轮输出一样。强行把字段抄平，反而会制造一种虚假的可比性。

## 7. Freeze B：摩擦输入是不是主导原因

Freeze B 专门改变 OVPhysX 的一类旧式关节摩擦输入，观察结果有多敏感。整个判断规则在运行前就固定好：变化很小才能支持“影响弱”，变化很大才能支持“影响强”，落在中间就必须承认证据不足。

结果：

- `24/24` case 完成；
- 新进程重复完全一致；
- 时间步长减半检查通过；
- 8 个灵敏度值中，`5/8 <= 0.10`，`3/8 > 0.10`，但 `0/8 >= 0.25`。

它既没有满足“几乎都很小”，也没有满足“足够多很大”。因此结论是 `VALID / INCONCLUSIVE`：实验有效，但不能支持“它影响很弱”或“它是主导因素”中的任何一个。

## 8. T1：不只做一下小阶跃，改成持续运动

Gate 0 的小阶跃像“轻轻拨一下关节”。T1 又加入两种持续变化的命令：

- sine：平滑、周期性来回；
- chirp：运动频率随时间逐渐变化。

结果：

- `32/32` case 完成；
- 共执行 `96,000` 个积分步；
- 所有数值有限，没有爆炸；
- 新进程重复完全一致；
- 时间步长减半检查通过；
- 四个“左/右手 × sine/chirp”单元的关节差与姿态差都在阈值内；
- 末端位置最大差约 `2.321–2.324 mm`，四个单元都超过 `2.000 mm`。

所以 T1 是 `VALID / DIVERGENT`。这说明毫米级末端位置差并不只出现在单次阶跃里，在持续轨迹中也能稳定复现。

## 9. C0：加入接触以后发生了什么

接触比无接触复杂得多。为了先确认测试方法是否稳定，C0 没有直接使用复杂原生指尖材料，而是设计了一个最小夹具：

- 在食指末端固定一个无质量小球；
- 场景中放一个静止盒子；
- 只允许指定的小球—盒子配对计入目标接触；
- 摩擦、回弹和重力都设为零，先减少无关变量；
- 关节按平滑曲线完成“压下—保持—松开—恢复”；
- 同时运行一组 sham，也就是没有真正目标接触的对照组。

sham 可以理解为医学试验里的安慰剂对照。它帮助区分“因为发生接触而产生的变化”和“即使没有接触，驱动动作本身也会产生的变化”。

C0 共 `32/32` case 完成，44 个关节和 10 个指尖相关坐标系覆盖完整，所有数值有限，两次新进程重复完全一致。

但有一个前置门没有通过：

- OVPhysX 在基础时间步长与减半时间步长下，判断“松开接触”事件中点的差为 `5.5 ms`；
- 预先定好的上限是 `4.0 ms`。

因此 C0 的正式结论是 `VALID / INCONCLUSIVE`，`pass_ready=false`。

这句话很重要：C0 不是“接触表现已经证明不同”。按照事先写好的判断顺序，必须先证明单个后端的事件对时间步长足够稳定，再做正式跨模拟器接触标签。前置门没过，所以项目在这里停下，没有偷跑后面的结论。

而且这个小球—盒子夹具只验证最小接触方法，不能外推到真实指尖、软材料、复杂抓取或硬件。

## 11. 这些标签到底是什么意思

### PASS

某一项检查满足了事先写好的规则。它不是对整个项目的无限担保。

### KNOWN

问题已知、有出处，或已经被上游处理。保留记录是为了不把别人的发现说成自己的。

### WARN

观察值得留意，但当前证据不足以判失败。

### DIVERGENT

至少一个比较指标超过预先设定的容差。它不是“官方 bug”的同义词，也不自动说明哪一个模拟器更接近现实。

### INCONCLUSIVE

实验有效，但证据没有满足任何一个预注册结论条件。说“暂时无法判断”比硬选一个答案更科学。

### UNMAPPABLE

两边可能都有数值，但没有足够证据说明它们语义等价，不能安全地做一一映射。

### pass_ready=false

当前证据包不满足“可以宣告通过”的条件。它不代表程序没跑完，而是科学门槛仍有未通过项。

## 12. 为什么这些数字值得相信

项目没有只保存一张截图或一份人工整理的 Excel，而是保留从输入到报告的完整证据链。

- 先冻结源码和实验清单，再运行；
- 每个正式 case 都在新进程中启动；
- 同一条件重新运行，检查能否精确重复；
- 把时间步长减半，检查结论是否依赖“时间刻度太粗”；
- 自动检查 case 数、步数、关节覆盖、坐标系覆盖、NaN 和数值爆炸；
- 原始证据与公开摘要分开保存，公开文件不带账号、机器路径等私密信息；
- 最终报告由离线程序从已封存证据生成，避免在远端临时手改结果；
- 当前自动化测试为 `937 passed`。

这些措施不能把仿真变成现实世界，但能让别人明确知道：测了什么、没测什么、用哪套规则测的、报告是否对应那次实验。

## 13. 最容易说错的六件事

1. **“497 PASS，所以跨模拟器也通过了。”**  错。497 是资产体检里的检查项，不是跨模拟器结论。
2. **“32/32 跑完，所以 C0 通过了。”**  错。跑完只证明执行完整；释放事件的时间步长稳定性仍没过线。
3. **“DIVERGENT 就是 PhysX 或 MuJoCo 有 bug。”**  错。它只表示超过项目预先设定的容差。
4. **“读到了相同数字，就说明参数等价。”**  错。两套引擎可能用不同定义、不同层次和不同算法解释它。
5. **“两次运行完全一样，所以数值一定准确。”**  错。可重复只说明稳定复现；dt-halving 才进一步检查时间离散影响。
6. **“仿真结果已经能代表真实机械手。”**  错。本项目没有做硬件实验或 Sim2Real。

## 14. 现在真正可以对外怎么说

可以说：

> 我为 Sharpa Wave 模型建立了一套可复现的资产质量检查和跨模拟器验证流程，覆盖标准左右手 44 个关节、10 个指尖相关坐标系，以及无接触阶跃、重力稳定、持续 sine/chirp 和最小合成接触实验。所有正式 case 均完整执行并通过重复性检查；实验同时如实报告了毫米级末端位置差、参数语义不可直接映射，以及接触释放事件对时间步长仍较敏感等限制。

不能说：

- “证明了两个模拟器等价”；
- “证明了某一引擎或官方资产存在 bug”；
- “证明了哪一个模拟器更接近真实世界”；
- “完成了完整 Isaac Sim 渲染验证”；
- “完成了硬件、Sim2Real、真实抓取或安全认证”。

给非技术同学的一句话版本：

## 16. 五个基础概念速查

### 自由度（DoF）

可以独立运动的变量数量。这里一只标准手有 22 个关节自由度，两只手合计 44 个。

### 前向运动学（FK）

已知每个关节转了多少，按几何关系算出指尖在哪里。它不考虑质量、摩擦和碰撞。

### 时间步长（dt）

模拟器每次把时间向前推进多少。dt 越小，通常计算越细，但更慢；结果随 dt 大幅变化，往往说明数值结论还不够稳。

### sham 对照

动作流程相同，但不发生目标接触的对照组，用来排除“动作本身”造成的变化。

### 可复现性

别人拿到同样的源码、输入和环境，能够重建同一实验并核对输出。它依赖明确的版本、清单、日志、哈希和自动检查，而不只是“我记得当时这样跑过”。
